返却デスク（仮称）導入チェックリスト（試験版向け・案）
※Stage A はデモのみ。実顧客データは Stage B の試験版で、バックアップ復元の確認後に扱う。
※1社ごとの専用コード分岐は作らない。差異は設定（拠点・チェック項目・役割）と CSV 対応表で吸収する。

1. CSV 対応表（既存ソフトの貸出明細 → 標準列）
  source_system ← 既存ソフト名（固定値）
  rental_id     ← 貸出／伝票番号（原文のまま。全半角を変えない）
  line_id       ← 明細番号
  site_code     ← 拠点コード（設定に登録済みのもの）
  customer_label← 顧客の表示名
  due_at        ← 返却予定（タイムゾーン付き ISO8601、例 2026-10-20T17:00:00+09:00）
  item_code / item_name / unit / qty_out（半角整数 1～9999）
  保存形式：Excel の「CSV UTF-8（コンマ区切り）」。Shift_JIS・xlsx は不可。5MB・2,000行まで。
  □ 既存ソフトから出力できる列を確認　□ 対応表を作成　□ samples/ の誤り例で検証画面の表示を確認

2. 役割
  operator（返却担当）：返却確認・写真・例外の提出
  reviewer（検品責任者・事務）：担当割当・承認・事務受領・CSV入出力（承認と受領を同一人物が行える。二者承認は保証しない）
  admin（組織管理者）：メンバー・設定・データ返却・完了後の訂正
  □ 各人の役割を決定　□ admin を2名以上推奨（最後の admin は停止不可）

3. 教育（目安 30分×2回）
  □ 返却入力（今回数は空欄から、全数ボタンも確認画面を通る）　□ 不足は「未返却」であり紛失・延滞ではない
  □ 写真は縮小保存、元写真は端末に残す　□ 保存済み・数量保存済み写真未完了・再確認が必要 の違い
  □ 通信断・タイムアウト時は「保存結果を確認」→ 再送（二重にならない）
  □ 請求候補 ≠ 請求書発行 ≠ 会計計上 ≠ 入金。CSV出力だけでは完了しない

4. 初期取込
  □ 試験対象期間の貸出だけを取込　□ 差分プレビューで追加件数を確認　□ 取込番号を記録

5. 顧客確認（契約前）
  □ 価格・支援上限・データ保持・終了時の返却方法の説明　□ 保守アクセスの理由・期間・合意の記録方法

6. 終了時のデータ返却
  □ admin がデータ返却ZIP（CSV・原文JSON・写真・manifest・README）を作成し、別環境で開けることを確認
  □ 書込停止日・受領期間30日・削除予定日を通知
